# 合约层去中心化加固（保留 Flap 九区 + 可升级架构）

保留你上传的这套九区架构（Beacon 可升级、Guardian、税收自动分配、无需许可补货），
只把「项目方能作恶」的地方在合约里堵死。服务器端的玩法规则（每日 6 次、120 分钟间隔、
同点位 24 小时）不变，仍由我们自己定。

## 现在合约里还存在的中心化风险

| 位置 | 风险 |
| --- | --- |
| `emergencyWithdrawNative` / `emergencyWithdrawToken` | Guardian 可以把金库里的 BNB 和股票代币全部提走 |
| `setGameConfig` | 可随时改签名者、改抽成比例、随时暂停领取 |
| `setGameDailyCap` | 每日额度没有上限，可以设成天文数字 |
| `setOpsTreasury` / `transferOwnership` | 收款地址和所有权可即时切换，无缓冲期 |
| `upgradeVaultImplementation` | 升级后逻辑可以任意改写（这是 Beacon 架构固有的） |

## 要做的改动

1. **提现只能提「多余的钱」**
   紧急提现前先算出：NFT 待领奖励 + 地图奖池 + 每区已承诺库存。低于这条线的资产任何人
   都提不走，Guardian 也不行。多余部分才允许救援（防止误转代币卡死）。

2. **所有敏感参数加 48 小时时间锁**
   `setGameConfig`（签名者、抽成、暂停）、`setOpsTreasury`、`transferOwnership`、
   `setGameDailyCap` 改成「提案 → 等 48 小时 → 执行」两步，并各自发事件。
   任何人都能提前看到即将发生的改动。

3. **参数写死硬上限**
   - 地图奖池抽成 ≤ 30%（不可再调高）
   - 每区每日发放额度 ≤ 该区库存的固定比例（例如 2%），且合约内绝对上限写死
   - 单张凭证金额上限写死
   这几条是常量，升级以外无法绕过。

4. **暂停只能暂停「领取」，不能暂停「退出」**
   暂停开关不影响 NFT 持有人 `claim` 分红，也不影响无需许可补货；只暂停地图凭证领取，
   且暂停最长 7 天后自动失效，防止无限期冻结。

5. **签名者支持多签地址 + 撤销即时生效**
   新增签名者需走 48 小时时间锁；**移除**签名者可即时执行（出事能立刻止血，方向只对用户有利）。
   上线时把签名者设为 2/3 多签合约地址。

6. **发放全程上链可审计**
   每次凭证领取都发出包含 `spawnId`、`to`、`token`、`amount`、`nonce` 的事件，
   并累计每区历史发放量，前端储备证明直接读链上真实余额，不再有任何合成数字。

7. **所有权路线**
   `owner` / `guardian` 交给 Flap 托管或时间锁合约；上线稳定后可调用一次性
   `renounce` 放弃「非救援类」管理权，只保留时间锁治理路径。

## 剩下的、合约堵不住的一点

到店 GPS 只能由服务器判断，凭证签名的私钥掌握在签名方手里 —— grass 也是一样。
我们比它多的保护是：链上每日硬额度 + 多签签名 + 48 小时时间锁 + 提现下限。
最坏情况下，签名方能超发的量被合约每日额度封顶，且每一笔都在链上留痕。
